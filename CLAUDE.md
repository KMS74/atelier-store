@AGENTS.md

## Project

Atelier Store: a Next.js 16 (App Router, `src/` dir, Turbopack) e-commerce app on TypeScript, Tailwind CSS v4, Better Auth, Drizzle ORM and Neon Postgres. So far there is a homepage and a product details page (`/products/[slug]`). Products, categories and stock come from Postgres; the rest of the storefront content is still editorial data in code. Auth is scaffolded only. Collection pages, cart, checkout, database schemas and sign-in methods don't exist yet, so many links point at routes that currently 404.

## Commands

- `npm run dev` / `npm run build` / `npm run start`
- `npm run lint` (ESLint 9 flat config, `eslint-config-next`)
- `npm run typecheck`: runs `next typegen` before `tsc --noEmit`. Global route types such as `LayoutProps` / `PageProps` are generated by Next, so plain `tsc` fails without typegen.
- `npm run auth:generate`: Better Auth CLI (the `auth` package; `@better-auth/cli` is deprecated, don't reintroduce it) writes auth tables to `src/db/auth-schema.ts`
- `npm run db:generate` / `db:migrate` / `db:push` / `db:studio`: drizzle-kit, migrations output to `drizzle/` (commit them)
- `npm run db:seed`: loads the sample catalog (`src/db/seed/products.ts`) via `tsx`. Idempotent: upserts by slug and replaces each product's images.

No test framework is configured.

## Environment

Copy `.env.example` to `.env.local` (a plain `.env` also works). Scripts that run outside Next (`drizzle.config.ts`, `src/db/seed.ts`) import `src/db/load-env.ts` first, which loads `.env.local` then `.env` with the first value winning, as Next does. `.gitignore` ignores `.env*` but whitelists `.env.example`.

`npm run build` queries the database (`generateStaticParams` and the homepage product rows), so it needs a reachable, migrated and seeded `DATABASE_URL`.

## Architecture

- `src/db/index.ts` exports `db`, a Drizzle client over Neon's HTTP driver (`drizzle-orm/neon-http`). It throws at import if `DATABASE_URL` is unset.
- `src/db/schema.ts` is the single schema entry point, used by both the Drizzle client and drizzle-kit. New table modules must be re-exported from it. The Better Auth tables are generated into `auth-schema.ts` and re-exported via the commented-out `export * from "./auth-schema";` line.
- `src/lib/auth.ts` is the Better Auth server instance, using `drizzleAdapter(db, { provider: "pg", schema })`. The `nextCookies()` plugin must remain last in `plugins`. Auth requests fail at runtime until the auth tables are generated, re-exported and migrated.
- `src/lib/auth-client.ts` is the React client (`better-auth/react`), with `baseURL` from `NEXT_PUBLIC_APP_URL`.
- `src/app/api/auth/[...all]/route.ts` mounts the auth handler via `toNextJsHandler(auth)`.
- Design tokens (monochrome palette, type scale, gutters, `text-label` / `px-page` utilities) live in `src/app/globals.css` as Tailwind v4 `@theme` / `@utility` blocks. Fonts are Jost (`font-sans`) and Bodoni Moda (`font-display`, wordmark only), loaded with `next/font` in `layout.tsx`. Rationale and usage rules are in `docs/design-reference.md`; use the tokens rather than raw colors or arbitrary sizes.
- Catalog tables live in `src/db/catalog-schema.ts`: `categories` (with an optional lifestyle `image_url` / `image_alt`), `products` (price as integer `price_cents`, `details` text[]), `product_images` (ordered by `position`) and `product_inventory` (one row per product; no row means sold out).
- Read products only through `src/db/queries/products.ts` (`getProduct`, `getProductsBySlugs`, `getRelatedProducts`, `getAllProductSlugs`). These map rows to the `Product` type in `src/lib/product.ts`: price in whole dollars, `stock` from inventory, and `images` as the product's own images followed by its category image. `src/lib/product.ts` also holds the stock and price helpers and must stay free of database imports, because client components use it too.
- Editorial content stays in `src/lib/catalog.ts`: hero, collections, menu, footer, and the hand-picked homepage rows as slug lists (`newArrivalSlugs`, `leatherGoodsSlugs`). Unsplash URL helpers are in `src/lib/unsplash.ts`. Components live in `src/components/`, with homepage sections in `src/components/home/`. `SiteHeader` (fixed, transparent over the homepage hero until it scrolls away) and `SiteFooter` are mounted in the root layout. Pages other than `/` need top padding (`pt-header`) because the header is fixed.
- `/` and `/products/[slug]` use `export const revalidate = 60`, so stock and price changes appear within a minute. Product pages are prerendered from `getAllProductSlugs()` with `dynamicParams = true`: products added after a build render on first visit, and unknown slugs 404 via `notFound()`. Stock state comes from `getStockState(stock)` in `src/lib/product.ts` (0 = sold out, up to `LOW_STOCK_THRESHOLD` = low stock) and is shared by `ProductCard` and the product page's `StockStatus`, so both always agree. "Add to Shopping Bag" is a placeholder that says the bag isn't available yet.
- The DB client uses neon-http, which has no interactive transactions. Use `db.batch([...])` for atomic multi-statement writes; switch to the WebSocket `Pool` driver when stock decrements need transactions.
- Render storefront photos with `StoreImage` (`src/components/store-image.tsx`), not `next/image` directly. It fills a `relative overflow-hidden` parent, puts a ~1 KB blurred Unsplash preview (`previewUrl()` in `src/lib/unsplash.ts`) underneath, and lets the full image paint over it as soon as it arrives. It never hides the image or waits for hydration: an earlier fade-in version delayed the first product image by 1.5–2 s on mobile. Failed images show an "Image unavailable" panel (`fallback-image.tsx`). Previews are loaded by the browser, so the build makes no image requests. Dim a whole image (e.g. sold out) on a wrapper element, not on the image itself.
- Images go through a custom global loader (`src/lib/image-loader.ts`, set in `next.config.ts`) that asks the Unsplash CDN for the right width, so the Next image optimizer isn't used. Images from other hosts pass through unresized. When an image is cropped with `object-cover` into a frame of a different shape, set `sizes` for the cropped width, not the frame width (see `hero.tsx`), or it will be blurry.
- Don't add `import "server-only"` to `src/db` or `src/lib/auth.ts`: the Better Auth CLI loads `auth.ts` outside Next, where that import throws.
